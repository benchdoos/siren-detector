# Данные и модели

## Структура датасета

Храните собственные записи отдельно от внешних справочных аудиоданных. Основные метки: `siren`, `explosion`, `uav`, `background` и `unknown`; длинные неразмеченные записи помещайте в `dataset/inbox/`.

```text
dataset/
├── siren/  explosion/  uav/  background/  unknown/
├── inbox/
└── external/esc50/
```

Аудиофайлы и локальные записи фона исключены из Git. Для скачанных датасетов сохраняйте атрибуцию и файлы лицензий. Подробности про ESC-50 и разметку записей — в `dataset/README.md`.

## Запись аудио через recorder

Сервис `recorder/` принимает UDP-аудио от Hub и сохраняет WAV-файлы на Linux-хосте. Работает как Docker-контейнер рядом с Hub.

```bash
cd recorder

# Записать 30 секунд фона
LABEL=background DURATION=30 docker compose run --rm recorder

# Записать 10 секунд сирены
LABEL=siren DURATION=10 docker compose run --rm recorder

# Непрерывная запись в inbox (остановка Ctrl-C)
docker compose run --rm recorder
```

Поддерживаемые метки: `siren`, `explosion`, `uav`, `background`, `unknown`, `inbox`. Файлы сохраняются в `dataset/recorder/<label>/` на хосте (bind mount). К каждой записи прикладывается JSON sidecar с метаданными (время начала/конца, sample rate, статистика пакетов).

Рекордер слушает порт `9001` по умолчанию (`RECORDER_PORT` в `.env`). Hub должен быть настроен на пересылку пакетов на этот порт.

После записи `make retrain` автоматически переносит файлы из `dataset/recorder/` в основные директории `dataset/` перед синхронизацией.

## Разметка через annotate_recording.py

Для длинных записей из inbox используйте `dataset/annotate_recording.py` для нарезки временных диапазонов:

```bash
# Абсолютные метки времени (по метаданным записи)
python3 dataset/annotate_recording.py dataset/inbox/20261009-070807.wav \
  --timezone Europe/Moscow \
  --segment siren 12:03 12:08 \
  --segment background 12:08 12:15

# Относительные метки (MM:SS от начала файла)
python3 dataset/annotate_recording.py dataset/inbox/20261009-070807.wav \
  --segment -f siren 0:03 5:08
```

Сегменты сохраняются как 5-секундные WAV-клипы в `dataset/<label>/` и логируются в `dataset/annotations.csv`.

## Разметка через Label Studio

Директория `label-studio/` содержит Docker Compose стек для браузерной разметки аудио с визуализацией формы волны.

### Настройка

```bash
cd label-studio
docker compose up -d
```

Запускаются два сервиса:

- **Label Studio** на `http://localhost:8080` — интерфейс разметки.
- **Аудио-сервер** (nginx) на `http://localhost:8081` — раздаёт WAV-файлы из `dataset/`, чтобы Label Studio мог их загрузить.

### Использование

1. Откройте `http://localhost:8080` и создайте проект.
2. В настройках проекта вставьте конфигурацию из `label-studio/labeling_config.xml`. Она определяет метки аудиосегментации: `siren` (горячая клавиша 1), `background` (2), `explosion` (3), `uav` (4), `unknown` (5).
3. Импортируйте задачи — вручную или по шаблону `label-studio/import.json`. Каждая задача ссылается на аудио с nginx-сервера (`http://localhost:8081/inbox/<filename>.wav`).
4. Размечайте, выделяя области на форме волны и назначая метки.
5. Экспортируйте аннотации и используйте `ml/ls_export.py` для конвертации в размеченные WAV-сегменты для обучения.

Предразметку от YAMNet можно импортировать через `ml/ls_import.py`, чтобы заполнить проект предсказаниями модели.

## Разметка через веб-интерфейс детектора

Веб-интерфейс детектора поддерживает разметку на месте. При подтверждении события сохраняется клип. Нажмите кнопку метки (siren / background / uav / unknown) — клип скопируется в `dataset/<label>/` на хосте. Также доступна сегментная разметка: выделите диапазон на спектрограмме, выберите метку, и сегмент будет вырезан и сохранён.

Калибровка фона записывает окружающий звук одного или нескольких выбранных источников одновременно в `dataset/background/<source>/`. Для всех источников задаётся одинаковая длительность; аудио каждого источника сохраняется отдельным WAV-файлом в его каталоге. Это помогает адаптировать фоновую модель к акустическому профилю каждого микрофона. Записывайте тихие, обычные и громкие условия.

## Готовые модели

Обученные веса и артефакты публикуются как GitHub Releases:
<https://github.com/benchdoos/siren-detector/releases>. Каждый релиз включает веса
MLP- и DSP-классификаторов, маппинг меток, метрики валидации, model card и
`saved_embeddings.npz` (замороженные эмбеддинги YAMNet из обучающего набора).

### Использовать релиз как есть

Скачайте zip релиза, извлеките файлы весов и скопируйте их в `ml/results/`:

```bash
unzip retrain-*.zip -d ml/results/
make deploy-model   # отправить веса на RPi и перезапустить
```

### Дотренировать релиз на своих данных

Скрипт обучения поддерживает инкрементальное переобучение. Если в `ml/results/` есть
`saved_embeddings.npz`, команда `make train` объединяет сохранённые эмбеддинги с
новыми, извлечёнными из вашего локального `dataset/`. Это позволяет добавить свои
записи без повторного извлечения эмбеддингов всего исходного датасета.

1. Скачайте релиз и положите `saved_embeddings.npz` (и опционально `classifier.keras`)
   в `ml/results/`.
2. Запишите и разметьте свои аудиозаписи (см. разделы выше).
3. Запустите аугментацию и обучение:

```bash
make augment
make train-dsp
make train
make deploy-model
```

Скрипт дедуплицирует по источнику: если файл есть и в сохранённых эмбеддингах,
и в вашем локальном датасете, приоритет у свежей версии.

### Собрать датасет с нуля

Релиз не обязателен. Запишите примеры через recorder или веб-интерфейс, разметьте,
при необходимости аугментируйте и обучите — полный цикл описан ниже и в разделах выше.

## Обучение и развёртывание

Обычный цикл переобучения запускается командой `make retrain`. Он переносит записи рекордера на хосте, дожидается завершения активной калибровки, синхронизирует данные, расширяет выбранные классы, обучает DSP- и MLP-классификаторы, проверяет результат и развёртывает доступные файлы моделей. Для этого цикла нужны SSH-адрес и URL веб-интерфейса в корневом `.env`.

Отдельные шаги:

```bash
make sync-dataset
make augment
make train-dsp
make train
make audit
make deploy-model
```

MLP обучается на замороженных эмбеддингах YAMNet; сам YAMNet проект не дообучает. Валидация разделяет данные по исходным записям, чтобы уменьшить утечку похожих сегментов между выборками. Оценивайте метрики каждого класса и матрицу ошибок, а не только общую точность. Оценки модели не являются откалиброванными вероятностями.

Рекомендации по балансу данных и проверке есть в `ml/TRAINING_GUIDE.md`, описание автономной оценки YAMNet — в `ml/README.md`, история аудитов — в `ml/AUDIT.md`.

## Аугментация

`dataset/augment.py` создаёт реалистичные обучающие сэмплы из чистых аудиоисточников (ESC-50, загрузки с Freesound), имитируя реальные условия записи на INMP441:

1. **Вариация громкости** — случайное усиление от -20 дБ до +3 дБ для имитации разного расстояния до источника звука.
2. **Смешивание с фоном** — наложение чистого сигнала на реальные записи фона INMP441 (из `dataset/background/`) при случайном SNR от -3 дБ до +20 дБ.
3. **Шумовой профиль** — опционально добавляет характерный шум микрофона INMP441, записанный в тишине (`--noise-profile dataset/background/noise-profile-inmp441.wav`).

Каждый аугментированный сэмпл — 5-секундный фрагмент, сохраняется как `dataset/<label>/aug_<source>_<hash>.wav`.

### Команды

```bash
# Аугментировать все классы (сначала удаляет старые aug-файлы)
make augment

# Отдельные классы
make augment-siren       # 172 сэмпла из ESC-50 + Freesound сирен
make augment-explosion   # 150 сэмплов из Freesound + конвертированных загрузок
make augment-uav         # 120 обычных + 40 тихих сэмплов

# Ручной запуск с параметрами
ml/.venv/bin/python dataset/augment.py siren --count 200 --noise-profile dataset/background/noise-profile-inmp441.wav
ml/.venv/bin/python dataset/augment.py uav --count 40 --quiet   # далёкие/приглушённые звуки
ml/.venv/bin/python dataset/augment.py siren --count 10 --dry-run  # предпросмотр без записи
```

### Режим quiet

Флаг `--quiet` генерирует сэмплы далёких/приглушённых звуков с пониженной громкостью (-30...-10 дБ) и худшим SNR (-6...+5 дБ). Полезен для UAV, где далёкие звуки типичны.

### Директории источников

| Метка | Источники |
|---|---|
| `siren` | `dataset/external/esc50_curated/siren/`, `dataset/external/freesound/audio/` |
| `explosion` | `dataset/external/esc50_curated/explosion/`, `dataset/explosion/dl_*.wav` |
| `uav` | `dataset/uav/dl_*.wav`, `dataset/uav/ls_*.wav` |

Фоны для смешивания берутся из `dataset/background/*.wav` (только записи INMP441 с датой в имени).

### Рекомендации

- Количество аугментированных сэмплов — не более ~2x от реальных в классе.
- `make clean-aug` удаляет все `aug_*` файлы перед перегенерацией.
- Всегда запускайте `make augment` перед `make train` (или используйте `make retrain`, который делает оба шага).

### Сравнение нескольких движков

Не ранжируйте движки по одной общей точности. Проверяйте все варианты на одной
версии размеченных записей, разделяя выборки по исходной записи, чтобы окна из
одного источника не попадали одновременно в обучение и проверку. Для каждого
класса сохраняйте precision, recall и F1, матрицу ошибок, число ложных событий
в час и задержку обнаружения. Записывайте версии движка и модели, настройки,
ревизию набора данных и оборудование. Оценки движков нельзя усреднять так, будто
это сопоставимые вероятности. Выбор остаётся ручным, пока не подготовлен
репрезентативный размеченный набор и согласованный критерий приемки.

## Качество данных

- Отдавайте предпочтение реальным записям с микрофонов и в условиях, где будет работать система.
- Старайтесь не превышать соотношение примерно два аугментированных примера на один реальный в классе, затем проверяйте метрики.
- Не используйте фейерверки как достоверные примеры взрывов, а короткие клипы ESC-50 — вместо записей для реальных условий.
- Не удаляйте данные с хоста, пока не синхронизировали их и не проверили результат обучения.
