# Авторизация и роли

Веб-интерфейс поддерживает три режима. Настройка выполняется в `hub/.env`, затем контейнер детектора нужно пересоздать.

| Режим | Настройки | Доступ |
|---|---|---|
| Без авторизации | `AUTH_ENABLED=false` | Все пользователи получают полный доступ. Используйте только в доверенной сети. |
| Токен | `AUTH_ENABLED=true`, `ADMIN_TOKEN=...` | Один bearer-токен администратора. Если токен не задан, он генерируется при старте и печатается в лог. |
| OIDC | `AUTH_ENABLED=true` и параметры `OIDC_*` | Вход через Keycloak или совместимый OpenID Connect провайдер; права задаются ролями. |

`ADMIN_TOKEN` работает и при включённом OIDC. Его можно оставить для аварийного входа и CLI-команд. Не передавайте его посторонним и не публикуйте в URL вручную.

## Роли

| Роль | Возможности |
|---|---|
| `viewer` | Смотреть оценки, события, клипы, аудио и доступные метрики. |
| `editor` | Всё из `viewer`, а также присваивать событиям метки и размечать сегменты клипов. |
| `admin` | Всё из `editor`, читать и менять настройки, управлять калибровкой и конфигурацией движков. |

Сервер проверяет права на API, WebSocket, загрузке клипов, аудио и спектрограмм. Скрытие кнопок в интерфейсе служит только для удобства и не заменяет серверную проверку. Открытие `/` показывает оболочку входа; данные и потоки требуют авторизации. Страница настроек и её API доступны только администратору.

## Подключение Keycloak

Создайте в Keycloak OIDC-клиент для веб-приложения. Используйте confidential client и Authorization Code flow. Добавьте точный Redirect URI:

```text
https://<публичный-хост>/auth/callback
```

Передайте приложению параметры:

```dotenv
AUTH_ENABLED=true
ADMIN_TOKEN=<длинный-случайный-токен-для-cli-и-резервного-входа>
OIDC_ISSUER_URL=https://<keycloak-хост>/realms/<имя-realm>
OIDC_CLIENT_ID=siren-detector
OIDC_CLIENT_SECRET=<секрет-клиента>
OIDC_SESSION_SECRET=<длинный-случайный-секрет-приложения>
OIDC_ROLE_CLAIM=realm_access.roles
OIDC_ROLE_MAP=siren-viewer=viewer,siren-editor=editor,siren-admin=admin
OIDC_COOKIE_SECURE=true
```

`OIDC_ROLE_CLAIM` задаёт путь к строке или списку ролей в ID token/userinfo. Добавьте этот claim в ID token через mapper или client scope Keycloak. Например, для realm roles используется `realm_access.roles`. `OIDC_ROLE_MAP` сопоставляет имена ролей провайдера с ролями приложения; здесь показаны пользовательские роли `siren-viewer`, `siren-editor` и `siren-admin`. Пользователь без совпавшей роли получит отказ.

Секреты должны быть случайными и уникальными. `OIDC_SESSION_SECRET` обязателен при включённом OIDC. Cookie сессии имеет флаги `HttpOnly`, `SameSite=Lax` и `Secure` при `OIDC_COOKIE_SECURE=true`. Используйте HTTPS и держите порт детектора закрытым извне за TLS reverse proxy. Для локальной разработки по HTTP можно временно указать `OIDC_COOKIE_SECURE=false`.

Приложение хранит OIDC-сессии в памяти и поддерживает один worker. Сессия истекает через 12 часов; после перезапуска детектора пользователи входят снова. Токен администратора при этом остаётся доступен CLI.

Чтобы вернуться к входу только по токену, удалите `OIDC_*` параметры, оставьте `AUTH_ENABLED=true` и задайте `ADMIN_TOKEN`. Чтобы полностью выключить проверку доступа, используйте `AUTH_ENABLED=false`.

## Retrain и CLI

Авторизация браузера не меняет локальный цикл `make retrain`. Цикл продолжает использовать `ADMIN_TOKEN` для опроса `/api/calibrate` и остановки калибровки перед синхронизацией датасета. Настройте тот же токен в `hub/.env` и в локальном окружении проекта.

Полный список защищённых маршрутов см. в [справочнике API](api.md), остальные параметры развёртывания — в разделе [эксплуатации](operations.md).
