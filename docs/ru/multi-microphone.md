# Подключение нескольких микрофонов

Detector принимает независимые аудиоисточники по UDP. У каждого источника собственный ID, буферы, состояние распознавания, история событий и имя. Hub пересылает пакеты, не меняя ID.

## USB-микрофон на Linux-хосте

Сервис в `audio_source/` получает звук с локального микрофона и отправляет его в Hub.

1. Подключите микрофон и убедитесь, что Linux его видит (`arecord -l`).
2. При необходимости укажите `AUDIO_SOURCE_ID=1` и `AUDIO_TARGET=127.0.0.1:9000` в `audio_source/.env`.
3. Запустите сервис на хосте: `cd audio_source && docker compose up -d`.
4. Добавьте к команде детектора `--source-name 1=rpi-usb`. В `hub/docker-compose.yml` эта привязка уже есть.

Для запуска без Docker установите зависимости из `audio_source/requirements.txt` и запустите `audio_source/audio_source.py`; список устройств можно получить с помощью `--list-devices`.

## Два INMP441 на одном ESP32

В прошивке для ESP32-S3 настроены две отдельные шины I2S:

| Сигнал | Микрофон 1 | Микрофон 2 |
|---|---:|---:|
| BCLK / SCK | GPIO4 | GPIO15 |
| LRCLK / WS | GPIO5 | GPIO16 |
| Данные | GPIO6 | GPIO17 |
| L/R | GND | GND |
| Питание | 3,3 В | 3,3 В |

Сейчас прошивка **смешивает (усредняет) сигналы двух микрофонов** и отправляет один поток SDR1 с ID источника `0`. Второй микрофон не отображается в детекторе как отдельный источник, и его включение не создаёт вторую запись источника. Если он отключён или молчит, первый микрофон продолжает передавать звук. Это одна смешанная аудиозапись, а не раздельное распознавание микрофонов.

Переключатель ESPHome `microphone_capture` одновременно запускает и останавливает оба микрофона. Второй микрофон нужно подключить к GPIO15/16/17. Конденсатор 100 нФ между VDD и GND у каждого микрофона может снизить шум питания.

## ID источников SDR1

В 12-байтовом заголовке пакета ID источника хранится как беззнаковое 16-битное число в сетевом порядке байтов, начиная со смещения 10. ID `0` — источник ESP32 по умолчанию. Детектор создаёт источник после первого корректного пакета, а для неизвестных ID использует имя `source-<id>`, если при запуске не указано повторяемое соответствие `--source-name ID=NAME`.

Собственный источник должен передавать моно-аудио 16 кГц, обрамлять данные заголовком SDR1, увеличивать последовательный номер пакета и иметь уникальный ID. Отправляйте пакеты на UDP-порт Hub (по умолчанию `9000`), чтобы они дошли до всех настроенных получателей.

## Последовательное и параллельное распознавание

Независимые источники обрабатываются в режиме `round_robin` (один цикл переключается между источниками) или `parallel` (отдельный цикл для каждого источника). Параллельная обработка может увеличить расход CPU и памяти. Эти режимы относятся к независимым ID SDR1; два микрофона, смешанные текущей прошивкой ESP32, в любом случае остаются одним источником.

На панели независимые источники объединяются в одну score-полосу: она показывает максимальную текущую оценку и самое приоритетное состояние (`confirmed` → `possible` → `idle`). Поэтому оценка и состояние могут относиться к разным микрофонам; подпись у полосы показывает источник, давший оценку. Когда DSP пропускает запуск YAMNet для источника, его последняя оценка затухает до нуля за три секунды, пока модель не выдаст новую.
