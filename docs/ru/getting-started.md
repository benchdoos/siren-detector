# Начало работы

## Что понадобится

- ESP32-S3 и один микрофон INMP441 (второй микрофон необязателен).
- Linux-хост с Docker Compose; основной сценарий развёртывания описан для Raspberry Pi.
- Для готовых образов на Raspberry Pi нужна 64-битная ОС (образы собираются для `linux/arm64`).
- Установка ESPHome для сборки и прошивки устройства.
- Сетевой доступ ESP32 к хосту, на котором работает Hub.

## 1. Настройте проект

Из корня репозитория:

```bash
cp .env.example .env
cp hub/.env.example hub/.env
cp esp32/secrets.yaml.example esp32/secrets.yaml
```

Укажите адрес целевого хоста и UDP-порт в файле секретов ESPHome. В корневом `.env` задайте SSH-адрес и URL веб-интерфейса, если собираетесь пользоваться командами развёртывания из Makefile. Эти два файла решают разные задачи: корневой файл настраивает команды Make, а `hub/.env` — Docker Compose.

Не добавляйте в Git реальные пароли Wi-Fi, токены администратора и другие секреты.

## 2. Прошейте ESP32

На компьютере с установленным ESPHome CLI из корня репозитория проверьте и соберите конфигурацию:

```bash
esphome config esp32/siren-detector.yaml
esphome compile esp32/siren-detector.yaml
```

Рядом с YAML-конфигурацией должен лежать `esp32/secrets.yaml` с параметрами `wifi_ssid`, `wifi_password`, `ap_password`, `udp_target_ip` и `udp_target_port` (шаблон — `esp32/secrets.yaml.example`). Для первой прошивки подключите ESP32-S3 по USB и выполните:

```bash
esphome run esp32/siren-detector.yaml
```

Выберите последовательный порт устройства, когда ESPHome предложит его. Последующие обновления можно передавать по OTA, когда устройство подключено к сети. Если сборка выполняется на другом хосте, перенесите YAML и secrets вместе, сохранив их расположение. Схема подключения микрофонов описана в разделе [Несколько микрофонов](multi-microphone.md); настройки прошивки и детектора — в [справочнике настроек](settings.md).

## 3. Запустите Hub и detector

На Linux-хосте выполните в каталоге развёртывания:

```bash
cd hub
docker compose up -d hub detector
```

Hub принимает звук ESP32 на UDP-порту `9000` и пересылает пакеты детектору на `9002`. Веб-интерфейс детектора доступен на порту `8080`.

Compose автоматически скачивает образы с тегом `latest`. Чтобы закрепить релиз, задайте `IMAGE_TAG` в `hub/.env`, например `IMAGE_TAG=v0.5.0`, затем перед запуском выполните `docker compose pull hub detector`. Эта настройка работает и в Compose-файлах остальных сервисов.

Откройте `http://<адрес-хоста>:8080`. При первом запуске файлы модели YAMNet загружаются и кэшируются; для этого нужен доступ к сети и время на первоначальную загрузку.

## 4. Проверьте передачу аудио

Убедитесь, что ESP32 в сети и отправляет пакеты, затем проверьте статус источника и аудио в веб-интерфейсе. Логи развёртывания можно смотреть командой `make logs` из настроенной рабочей копии или командой `docker compose logs -f hub detector` на хосте.

## Локальная разработка

Чтобы собрать и запустить Hub и Detector из локального исходного кода на Raspberry Pi, выполните из каталога `hub/`:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build hub detector
```

Для USB audio source и recorder в их каталогах есть такие же файлы `docker-compose.build.yml`. Основные Compose-файлы без дополнительной конфигурации скачивают опубликованные образы. Detector также можно запустить напрямую через Python: установите зависимости из `detector/requirements.txt` и выполните `python -m detector.main`; UDP-порт по умолчанию — `9000`, веб-порт — `8080`.
