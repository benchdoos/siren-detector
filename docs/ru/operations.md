# Эксплуатация

Перед обновлением установленной системы см. [руководство по переходу и
обновлению](migration.md): там описаны резервная копия `clips`, сохранение
production `.env` и активация графа нескольких решений.

## Сервисы и порты

| Сервис | Порт по умолчанию | Назначение |
|---|---:|---|
| UDP Hub | `9000` | Принимает пакеты ESP32 и других аудиоисточников |
| UDP рекордера | `9001` | Получатель Hub во время записи |
| UDP детектора | `9002` | Получатель Hub для распознавания |
| Веб-интерфейс и API детектора | `8080` | Панель, настройки и HTTP API |

Порты можно изменить в `hub/.env`. В предоставленном Compose detector использует сетевой режим host.

## Развёртывание с компьютера разработчика

После настройки корневого `.env` доступны основные цели Makefile:

```bash
make deploy       # синхронизировать код детектора и обновить сервис
make deploy-ui    # синхронизировать только файлы веб-интерфейса
make logs         # смотреть логи детектора на настроенном хосте
make restart      # перезапустить контейнер детектора
```

Чтобы обновить сервис через Compose непосредственно на хосте:

```bash
cd hub
docker compose up -d --build detector
docker compose logs -f detector
```

## Веб-интерфейс и настройки

Веб-интерфейс доступен по адресу `http://<хост>:8080`. На панели отображаются текущие оценки, источники, история событий и сохранённые клипы. Страница настроек управляет порогами классов, сглаживанием, паузами между событиями, аудиоисточниками и режимом распознавания. Настройки детектора и клипы сохраняются в Docker-томе `clips`. Значения по умолчанию, диапазоны и назначение параметров перечислены в [справочнике настроек](settings.md).

Панель и страница настроек доступны на русском и английском языках. Переключатель находится в шапке страницы; выбранный язык сохраняется в браузере. При первом посещении используется предпочтительный язык браузера, если это русский; в остальных случаях включается английский.

Авторизация задаётся параметрами `AUTH_ENABLED` и `ADMIN_TOKEN` в `hub/.env`. Если авторизация включена, а токен не задан, детектор создаёт его при запуске; посмотрите логи контейнера. Не раскрывайте токен.

## MQTT и Home Assistant

MQTT необязателен. Укажите `MQTT_HOST`, `MQTT_PORT` и, если нужно, `MQTT_USER`/`MQTT_PASSWORD` в `hub/.env`, затем пересоздайте контейнер детектора. При доступном брокере интеграция публикует состояние и события в пространстве топиков `sound_detector` и поддерживает обнаружение Home Assistant. `sound_detector/events` содержит JSON-сообщения с `engine_id`, `source_id`, именем источника, событием, состоянием, confidence и timestamp; существующие retained-топики Home Assistant сохраняются.

## Webhook

Задайте `WEBHOOK_URLS` — список HTTP(S) адресов через запятую. На них отправляются POST-запросы с JSON `detector-event.v1`. Переменная `WEBHOOK_TOKEN` опционально добавляет общий Bearer token, а `WEBHOOK_TIMEOUT_SECONDS` задаёт timeout каждого адреса (по умолчанию 2 секунды). События отправляются через ограниченную очередь на 128 элементов; при переполнении отбрасывается самое старое ожидающее событие. Ошибки запросов логируются и видны в Settings → Runtime; повторной отправки нет. Webhook получает события, но не score updates.

## HTTP и WebSocket API

Подробный перечень маршрутов и правила доступа вынесены в [справочник API](api.md). Интерактивная REST-документация FastAPI доступна по адресу `http://<хост>:8080/docs`, спецификация OpenAPI — `http://<хост>:8080/openapi.json`.

API работает на том же порту, что и веб-интерфейс. Основные маршруты:

| Маршрут | Метод | Назначение |
|---|---|---|
| `/api/settings` | GET/POST | Читать и обновлять настройки (POST требует права администратора) |
| `/api/sources` | GET | Получить список известных источников |
| `/metrics` | GET | Считать Prometheus-счётчики и gauges runtime (нужен Viewer token) |
| `/api/metrics` | GET | Прочитать метрики валидации, если они есть |
| `/api/audits` | GET | Получить снимки аудита модели и датасета |
| `/api/calibrate` | GET/POST | Проверить статус или начать калибровку фона |
| `/api/calibrate/stop` | POST | Завершить и сохранить калибровку |
| `/api/calibrate/cancel` | POST | Отменить калибровку |
| `/feedback` | POST | Разметить сохранённый клип |
| `/ws` | WebSocket | Текущие события, оценки и состояние |
| `/ws/audio` | WebSocket | Поток PCM-аудио в реальном времени |

При включённой авторизации маршруты просмотра требуют действующий токен, а изменяющие состояние — права администратора. Полный перечень маршрутов и форматы API приведены в [справочнике API](api.md) и в Swagger UI работающего сервера.

## Справочник Makefile

Все цели предполагают, что в корневом `.env` настроены `RPI`, `RPI_BASE`, `CONTAINER` и `WEB_UI`.

### Развёртывание

| Цель | Описание |
|---|---|
| `make deploy` | Полная пересборка: синхронизация detector + Compose на RPi, пересборка контейнера. |
| `make deploy-ui` | Только `detector/static/` (без пересборки контейнера). |
| `make deploy-audio` | Синхронизация `audio_source/` на RPi и пересборка его контейнера. |
| `make deploy-firmware` | Копирование YAML ESP32 на RPi, валидация, компиляция, прошивка OTA. |
| `make deploy-compose` | Копирование `hub/docker-compose.yml` на RPi (без пересборки). |
| `make deploy-model` | Отправка весов (MLP + DSP + аудиты) на RPi и перезапуск. |
| `make restart` | Перезапуск контейнера детектора (без пересборки). |
| `make logs` | Просмотр логов контейнера детектора. |
| `make logs-esp` | Просмотр логов ESP32 через ESPHome на RPi. |

### ML и переобучение

| Цель | Описание |
|---|---|
| `make retrain` | Полный цикл: merge recorder → sync → augment → train DSP + MLP → audit → deploy → clean. |
| `make sync-dataset` | Синхронизация размеченных данных с RPi на Mac. |
| `make augment` | Аугментация siren + explosion + uav (сначала удаляет старые `aug_*`). |
| `make augment-siren` | Аугментация только класса siren. |
| `make augment-explosion` | Аугментация только класса explosion. |
| `make augment-uav` | Аугментация UAV (обычные + тихие). |
| `make train` | Обучение MLP-классификатора на локальном датасете. |
| `make train-dsp` | Обучение DSP-фильтра (Conv1D на DSP-фичах). |
| `make audit` | Аудит датасета и модели, сохранение снимка. |
| `make audit-compare` | Сравнение последнего аудита с предыдущим (или `OLD=file NEW=file`). |
| `make package-retrain-release` | Упаковка результатов переобучения для GitHub Release. |

### Очистка

| Цель | Описание |
|---|---|
| `make clean-clips` | Удаление всех сохранённых клипов на RPi. |
| `make clean-dataset` | Удаление всех размеченных WAV на RPi (сначала синхронизируйте!). |
| `make clean-aug` | Удаление всех локальных `aug_*` файлов перед перегенерацией. |
| `make clean-docker` | Очистка Docker-образов и кэша сборки на RPi (тома сохраняются). |

### Утилиты

| Цель | Описание |
|---|---|
| `make settings` | Вывод текущих runtime-настроек детектора в JSON. |
| `make open` | Открытие веб-интерфейса в браузере. |
| `make unlock` | Добавление SSH-ключа в агент на 10 минут. |
| `make fetch-esc50` | Скачивание и распаковка датасета ESC-50. |
| `make help` | Показать доступные команды. |

## Устранение неполадок

- **Источник не появляется:** проверьте логи ESPHome, целевой IP и порт, а также доступность UDP `9000` на хосте Hub.
- **Hub получает звук, но detector — нет:** проверьте `DETECTOR_PORT` и настройки пересылки в `hub/docker-compose.yml`.
- **Событий нет:** убедитесь, что нужный источник включён, проверьте пороги и сглаживание, сначала посмотрите текущие оценки.
- **Первый запуск медленный:** при первом использовании YAMNet загружается и кэшируется в Docker-томе.
- **Высокая загрузка процессора:** используйте `round_robin`, увеличьте интервал распознавания или отключите необязательные этапы обработки.
