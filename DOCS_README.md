# Документация проекта

Документация хранится в Markdown и публикуется как сайт на GitHub Pages с помощью MkDocs Material и плагина `mkdocs-static-i18n`.

## Структура

- `docs/en/*.md` — версия на английском языке (основной язык сайта).
- `docs/ru/*.md` — русские переводы с такими же именами файлов.
- `mkdocs.yml` — тема, меню и настройки локализации.
- `docs/requirements.txt` — зависимости сборки документации.
- `.github/workflows/docs.yml` — автоматическая сборка и публикация.

Добавляя страницу, создай английскую версию и перевод с одинаковым именем файла в `docs/en/` и `docs/ru/`, затем добавь её в меню `nav` в `mkdocs.yml` (путь указывается без префикса локали). Ссылки на соседние страницы оформляй относительными Markdown-ссылками.

## Локальный просмотр и сборка

```bash
python3 -m venv .docs-venv
. .docs-venv/bin/activate
python -m pip install -r docs/requirements.txt
mkdocs serve
```

Команда `mkdocs build --strict` собирает обе локали и завершится с ошибкой при предупреждениях. GitHub Actions выполняет эту команду при изменении документации, конфигурации сайта или самого workflow в ветке `main`, затем публикует сайт через GitHub Pages.

Для первой публикации в настройках репозитория открой **Settings → Pages** и выбери **GitHub Actions** как источник сборки.
