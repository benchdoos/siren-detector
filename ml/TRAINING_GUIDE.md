# Training Guide — Audio Event Detection

Руководство по обучению MLP-классификатора поверх YAMNet embeddings.
Основано на практическом опыте проекта и исследованиях в области Environmental Sound Classification.

## Архитектура

```
Audio (16kHz mono) → YAMNet (frozen) → 1024-dim embedding (per 0.96s window) → MLP head → class
```

YAMNet предобучен на AudioSet (>2M клипов, 521 класс). Мы не дообучаем YAMNet — используем его как feature extractor. MLP-голова учится классифицировать embeddings по нашим классам: `siren`, `explosion`, `motorcycle`, `background`.

## Аугментация

### Что делает augment.py

Берёт чистые источники (ESC-50, Freesound) и создаёт реалистичные тренировочные данные:
- Варьирует громкость (имитация расстояния до источника)
- Подмешивает реальные фоновые записи с INMP441 микрофона
- Опционально накладывает шумовой профиль микрофона

### Оптимальное соотношение aug/real

| Соотношение | Эффект |
|---|---|
| ≤ 1:1 | Безопасное улучшение, минимальный риск |
| 2:1 | Обычно ещё помогает, diminishing returns |
| 3-5:1 | Diminishing returns, модель начинает учить артефакты аугментации |
| > 5:1 | **Деградация.** Модель учит распределение синтетики, а не реальных звуков |

**Правило:** aug-файлов не больше чем 2x от реальных. Если 60 реальных motorcycle → максимум 120 aug.

### Domain gap — главная ловушка

Аугментированные файлы проходят через YAMNet и дают embeddings, **отличающиеся** от реальных INMP441 записей. Причина — микрофон INMP441 имеет свою АЧХ, шум, динамический диапазон. YAMNet это "видит" в спектрограмме.

Когда синтетика доминирует (>80% датасета), MLP учит ESC-50/Freesound распределение embeddings, а не INMP441. На реальных данных accuracy падает.

**Решение:** sample weights — реальные данные весят больше, чем аугментированные (real=1.0, aug=0.3–0.5).

### Какие техники работают

| Техника | Применимость | Комментарий |
|---|---|---|
| Volume + SNR mixing | Да, основа | Уже реализовано в augment.py |
| Pitch shift ±2 semitones | Да, для сирен | Разные сирены звучат на разных частотах |
| Time shift ±0.5s | Да, бесплатно | Сдвиг аудио → другое окно → другой embedding |
| Mixup на embeddings | Да, эффективно | Смешивание двух embeddings, λ ~ Beta(0.2, 0.2) |
| Dropout на embeddings | Да | Зануление 10-20% фичей при обучении MLP |
| SpecAugment | Нет | Работает на спектрограммах, не на готовых embeddings |

## Class Imbalance

### Проблема

Типичная ситуация: background ~7000 windows, motorcycle ~200 windows (35:1).
Модель "ленится" — предсказывает background и получает высокий общий accuracy за счёт доминирующего класса.

### Решения (от простого к сложному)

**1. Class weights в loss (рекомендуется)**

Формула: `weight = sqrt(N_total / N_class)`

Не использовать `1/N_class` — слишком агрессивно, модель начнёт переоценивать minority class.

**2. Undersample background**

Вместо 7000 background windows брать ~1500-2000 (2-3x от среднего по остальным классам).
Простой способ — ограничить `MAX_WINDOWS_PER_FILE` для background.

**3. Focal loss**

Снижает вклад "лёгких" примеров (правильно предсказанный background) и фокусирует обучение на "трудных" (пропущенная сирена).

```
FL(p) = -α(1-p)^γ * log(p)
```

Стандартные значения: `γ = 2`, `α` = inverse class frequency.

**4. Не рекомендуется: oversample minority class**

Дублирование minority файлов ведёт к переобучению на конкретные примеры.

## Validation

### Разделение по source

Train/val split должен быть **по source recording**, а не по файлам. Иначе аугментированный файл и его источник могут попасть в разные множества → data leakage → завышенные метрики.

Текущая реализация: `source_name()` извлекает base name, val split по unique sources.

### Что смотреть

- **Per-class accuracy** — общий accuracy обманчив при дисбалансе
- **Confusion matrix** — показывает какие классы путаются друг с другом
- **val_metrics.json** — сохраняется автоматически при каждом обучении

## Фильтрация данных

### Нулевые окна (UDP drops)

ESP32 передаёт аудио по UDP. При потере пакетов вставляются нулевые сэмплы.
`train_classifier.py` автоматически отбрасывает окна где >50% сэмплов == 0.0.

### Длительность клипов

`clip_seconds` (настройка в UI, default: 10) — длительность аудио, сохраняемого при confirmed event. Чем короче клип, тем меньше фоновых окон ошибочно размечаются как событие.

30 секунд: ~25с фона + ~5с события → 80% окон с неверным лейблом.
10 секунд: ~5с фона + ~5с события → 50% окон с неверным лейблом.

## Чеклист перед ретрейном

1. Проверить соотношение aug/real по классам (aug ≤ 2x real)
2. Убедиться что background не доминирует (>5x от остальных)
3. Проверить что val split по source, а не по файлам
4. Посмотреть confusion matrix — какие классы путаются?
5. Новые реальные данные > новая аугментация
